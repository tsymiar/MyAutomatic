webevs 的构建：两个入口两套落点，且规则挂在文件上

./build.sh webevs 因目录内有 CMakeLists 而在 webevs/build/ 就地构建；make -C webevs build（顶层 all 的第 4 步）才走该 Makefile，用共用的 LinxSrvc/build 并把二进制拷进 gen/。又因为构建规则的目标是目录里的 Makefile 文件本身，一旦生成过，make -C webevs make-all 会判为「已最新」空转，仍需用 make -C webevs build（= clean + make-all）强制重建。

⚠️ 风险与待办清单

Risk Register

🔴 多套构建系统共用目录 High

CMake 链与 Make 链各自为政，LinxSrvc/build 被两者共用，多个子项目同时以 ../gen 为输出目录；一处 clean 可能清掉另一处的中间文件。

🟡 IM 账号落盘格式脆弱 Medium

用户/群组表以裸结构体 fwrite 写 accounts 文件，字段一改即不可读，且不跨平台（含 MAX_ACTIVE 差异）。

🟡 IM 命令执行面 Medium

EXEC/IMAGE 分支直接 execvp("imgfilesnap.exe")（RASPI 下为 raspistill），属于外部命令执行面，需约束输入。

🟡 gSOAPverify 静默成功 / 误挪 .o Medium

缺 MySQL 库时 Makefile 仍打印 SUCCESS 但不产出 ELF；mv $(CUR)/../*.o 会把相邻工程的中间文件一起搬走；make install 会 killall -9 并写系统目录。

🟡 线程池共享同一块栈 Medium

thread/pthdpool.c 把一整块 pool->stack（STK_SIZE 10*4096）传给所有 worker，不符合每线程独立栈的正常使用方式。

🟡 脚本内明文口令 Medium

shell/expect/*（autossh、8927 端口脚本）与 shell/x64mk/env.sh 残留明文口令 / token 占位，shell/shadowsocks.sh 使用了固定口令。

🟡 WS 默认广播语义 Medium

未注册 WsOnMessage 时，WS 服务默认把收到的消息广播给全部连接；对外提供服务需显式注册并鉴权。
